## Ringkasan proyek

Aplikasi pelaporan Standar Pelayanan Minimal (SPM) RSUD, dibangun dengan:

- React 19 + TypeScript + Vite 8
- Supabase (auth + database, RLS aktif)
- Oxlint untuk lint
- lucide-react untuk ikon

## Struktur direktori

- `src/App.tsx` — memetakan rute aktif (dari `useRouter`) ke komponen fitur; guard halaman tak diizinkan ? Ringkasan.
- `src/features/` — kode per fitur: `dashboard`, `reports`, `indicators`, `audit`, `settings`, `users`.
- `src/components/` — komponen bersama: `layout/AppShell`, `layout/NotificationBell` (dropdown notifikasi di topbar), `layout/UserMenu` (menu pengguna di topbar: badge nama peran, avatar, nama, dropdown Log Out), `feedback/ProgressBar` (top progress bar hijau global via `ProgressProvider` + hook `useProgress`), dan `feedback/ConfirmDialog` (modal konfirmasi bersama: keluar, hapus indikator/unit/profil).
- `src/auth/` — autentikasi. Tampilan login memakai tema hijau selaras dashboard (`--forest` / `#173e36`).
- `src/assets/` — aset yang di-bundle Vite (mis. `logo-rsud-ami.png` untuk UI).
- `public/` — aset statis disajikan di root (mis. `logo-rsud-ami.png` untuk favicon).
- `src/types/` — tipe bersama (mis. `AppPage`, tipe SPM).
- `src/data/` — data/konstanta.
- `src/lib/` — util bersama: `spm-data.ts`, `spm-achievement.ts`, `access.ts` (akses menu peran+izin), `routes.ts` (peta rute hash + `routeFromHash`/`hashForRoute`), `router.tsx`/`routerContext.ts` (routing hash + hook `useRouter`), `supabase.ts`.
- `src/styles/` — stylesheet global (`app.css`).
- `tests/` — uji vitest (di **luar** `src` agar `tsc -b`/build tidak memeriksa berkas uji) + `tests/support/fake-supabase.ts` (klien Supabase palsu in-memory). **Klien palsu (2026-10-16):** `FakeDatabase` berisi `units`, `profiles`, `indicators`; `insert` **mengisi `id` otomatis** (`fake-N`) dan meniru `unique` pada kolom `code` ? error `23505`; `.single()` dengan 0/lebih dari 1 baris ? error `PGRST116` (meniru PostgREST). **Penting saat menulis tes halaman:** mock `getSupabaseClient` **wajib mengembalikan satu instance klien yang stabil** (bikin sekali di dalam factory `vi.mock`, bukan per pemanggilan) — kalau tidak, `client` berubah identitas setiap render, `useEffect` halaman ikut jalan lagi, data dimuat ulang dari DB, dan **bug tersembunyi** (mis. seperti bug edit-indikator 2026-10-16).
- `vitest.config.ts` — konfigurasi uji (environment `jsdom`, `include: tests/**/*.test.{ts,tsx}`).
- `supabase/migrations/` — migrasi database (urutannya penting, lihat README).
- `supabase/setup/` — skrip perbaikan/setup manual.

## Alur commit, push, dan deploy

**Standing order (2026-11-05):** perintah pengguna **"commit dan push"** = izin penuh untuk satu rangkaian: commit ? push ? **jalankan workflow `Deploy to GitHub Pages`** ? pantau sampai selesai ? verifikasi situs live ? laporkan hasil. Jangan berhenti di push dan jangan menunggu pengguna menjalankan workflow secara manual.

1. **Prasyarat:** `npm run lint`, `npm test` (atau `npx vitest run --no-file-parallelism`), `npm run build` sudah hijau, dan `PROGRESS.md` + `AGENTS.md` sudah diperbarui.
2. **Commit + push:** `git add` berkas yang relevan (jangan sertakan `.env.local`/secret), `git commit` dengan pesan gaya repo, `git push` ke `main` (tanpa ubah config git, tanpa force-push).
3. **Trigger deploy via REST API** (`gh` CLI tidak terpasang; token diambil dari Git Credential Manager, **jangan pernah dicetak/di-commit**):
   ```powershell
   $cred = ("protocol=https`nhost=github.com`n`n" | git credential fill 2>$null) -split "`n"
   $token = (($cred | Where-Object { $_ -like "password=*" }) -replace "password=","")
   $headers = @{ Authorization = "Bearer $token"; Accept = "application/vnd.github+json"; "User-Agent" = "opencode" }
   $body = @{ ref = "main" } | ConvertTo-Json
   Invoke-RestMethod -Method Post -Headers $headers -ContentType "application/json" `
     -Uri "https://api.github.com/repos/rantemario905-source/SPM-RSUD-AMI/actions/workflows/deploy.yml/dispatches" -Body $body
   ```
4. **Pantau run** sampai `conclusion` final:
   ```powershell
   Invoke-RestMethod -Headers $headers -Uri "https://api.github.com/repos/rantemario905-source/SPM-RSUD-AMI/actions/workflows/deploy.yml/runs?per_page=1" |
     ForEach-Object { $_.workflow_runs[0] | Select-Object run_number, status, conclusion, head_sha, html_url }
   ```
   Ulangi tiap ±15–30 detik sampai `status = completed`. Jika `conclusion` bukan `success`, laporkan gagal + tautan run dan **jangan** klaim deploy berhasil.
5. **Verifikasi live** setelah `success`: ambil `https://rantemario905-source.github.io/SPM-RSUD-AMI/` ? baca `index.html` ? catat nama berkas `assets/index-*.js`; pastikan hash-nya berbeda dari deploy sebelumnya (hash JS live berbeda dari build lokal itu wajar karena CI memakai `base: '/SPM-RSUD-AMI/'`). Opsional: pastikan bundle memuat `sb_publishable_` dan tidak memuat `eyJ`.
6. **Laporkan setiap deploy** dengan format ringkas: nomor run + kepala commit + kesimpulan + tautan run + nama berkas JS/CSS live + status migrasi DB (bila ada migrasi baru yang **wajib dijalankan pengguna**, sebutkan eksplisit). Catat run tersebut di `PROGRESS.md`.
7. Tanpa perintah eksplisit pengguna, jangan commit/push/deploy sama sekali.
