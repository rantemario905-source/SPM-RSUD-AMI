Dokumen ini dibaca otomatis oleh agen/editor di awal sesi. Isinya konteks proyek, konvensi, dan cara melanjutkan pekerjaan. **Selalu baca `PROGRESS.md` juga** sebelum mulai bekerja.

## Ringkasan proyek

Aplikasi pelaporan Standar Pelayanan Minimal (SPM) RSUD, dibangun dengan:

- React 19 + TypeScript + Vite 8
- Supabase (auth + database, RLS aktif)
- Oxlint untuk lint
- lucide-react untuk ikon

## Struktur direktori

- `src/App.tsx` — memetakan rute aktif (dari `useRouter`) ke komponen fitur; guard halaman tak diizinkan → Ringkasan.
- `src/features/` — kode per fitur: `dashboard`, `reports`, `indicators`, `audit`, `settings`, `users`.
- `src/components/` — komponen bersama: `layout/AppShell`, `layout/NotificationBell` (dropdown notifikasi di topbar), `layout/UserMenu` (menu pengguna di topbar: badge nama peran, avatar, nama, dropdown Log Out), `feedback/ProgressBar` (top progress bar hijau global via `ProgressProvider` + hook `useProgress`), dan `feedback/ConfirmDialog` (modal konfirmasi bersama: keluar, hapus indikator/unit/profil).
- `src/auth/` — autentikasi. Tampilan login memakai tema hijau selaras dashboard (`--forest` / `#173e36`).
- `src/assets/` — aset yang di-bundle Vite (mis. `logo-rsud-ami.png` untuk UI).
- `public/` — aset statis disajikan di root (mis. `logo-rsud-ami.png` untuk favicon).
- `src/types/` — tipe bersama (mis. `AppPage`, tipe SPM).
- `src/data/` — data/konstanta.
- `src/lib/` — util bersama: `spm-data.ts`, `spm-achievement.ts`, `access.ts` (akses menu peran+izin), `routes.ts` (peta rute hash + `routeFromHash`/`hashForRoute`), `router.tsx`/`routerContext.ts` (routing hash + hook `useRouter`), `supabase.ts`.
- `src/styles/` — stylesheet global (`app.css`).
- `tests/` — uji vitest (di **luar** `src` agar `tsc -b`/build tidak memeriksa berkas uji) + `tests/support/fake-supabase.ts` (klien Supabase palsu in-memory).
- `vitest.config.ts` — konfigurasi uji (environment `jsdom`, `include: tests/**/*.test.{ts,tsx}`).
- `supabase/migrations/` — migrasi database (urutannya penting, lihat README).
- `supabase/setup/` — skrip perbaikan/setup manual.

## Konvensi

- Stylesheet diletakkan dekat modul pengguna (mis. `ReportsPage.css` di sebelah `ReportsPage.tsx`).
- Setiap halaman fitur = 1 komponen `*.tsx` dengan `PascalCase`.
- **Jangan tambahkan komentar pada kode** kecuali diminta.
- Jangan pernah menaruh `service_role` key atau kata sandi di kode/Git. Hanya publishable/anon key di frontend.
- **Key Supabase & deploy:** frontend memakai key **publishable** (`sb_publishable_…`). Nilai di `.env.local` dan secret GitHub Actions `VITE_SUPABASE_ANON_KEY` harus **sama**; secret hanya terpakai saat workflow build berjalan, jadi **setiap mengubah secret wajib menjalankan ulang** *Deploy to GitHub Pages*. Verifikasi cepat: nama file bundle JS di situs live berubah dan isinya memuat `sb_publishable_` (bukan `eyJ…`).
- Jangan simpan data identitas pasien; hanya capaian agregat SPM.
- Ikuti pola yang sudah ada pada fitur tetangga sebelum membuat pola baru.
- Akses data: semua pengguna terautentikasi boleh **membaca** laporan/entri semua unit, tetapi hanya boleh **menulis** untuk unit yang dipegang profilnya (`profiles.unit_ids`; `manage_users`/`view_all_reports` boleh semua unit). UI Input laporan menampilkan semua unit, unit lain hanya-baca.

Peta rute di `src/lib/routes.ts` (`routeHashes`, `routeFromHash`, `hashForRoute`, `isAppPage`). `src/lib/router.tsx` mengekspor `RouterProvider` (dipasang di `main.tsx` di atas `AuthGate`); hook `useRouter()` (`route`, `navigate(route, { replace? })`) ada di `src/lib/routerContext.ts`, memakai `pushState`/`replaceState` + listener `popstate`/`hashchange`. `App.tsx` menurunkan halaman dari `route` + guard izin. `AuthGate` mengelola rute `login`: tanpa sesi → `#/login`; sesi aktif + rute `login` → tampilkan layar login **tanpa logout** (inilah tujuan tombol Back); setelah login → `pushState` `#/dashboard`; saat sesi bertahan (refresh) ia menyisipkan entri `#/login` di belakang halaman aktif agar Back tidak langsung keluar situs. Hasil: tombol Back/Forward menelusuri riwayat menu lalu kembali ke layar login. Jangan kembalikan navigasi ke state-saja.
- **Sidebar menetap (desktop ≥681px, 2026-10-14):** `AppShell.css` menyetel `.app-frame`/`.sidebar`/`.main-column` setinggi `100vh`; hanya `.page-content` yang `overflow-y: auto` (topbar & footer tetap di tempat). Menampilkan badge **nama peran** (latar hijau muda), avatar inisial, dan **nama pengguna** dari `profiles.full_name` (fallback email); diklik membuka menu kecil berisi **Log Out** (memicu `ConfirmDialog` yang sama). `AuthContext`/`AuthGate` kini juga menyediakan `fullName`. ## Perintah

- `npm run dev` — server pengembangan.
- `npm run lint` — Oxlint (jalankan setelah perubahan).
- `npm test` — vitest (`vitest run`, jsdom). Cakupan: `tests/`.
- `npm run build` — typecheck (`tsc -b`) + build produksi.
- Verifikasi wajib setelah mengubah kode: `npm run lint`, `npm test`, dan `npm run build`.

## Alur kerja agen

1. Baca `PROGRESS.md` untuk status pekerjaan terakhir.
2. Periksa `git log --oneline -10` dan `git status` untuk konteks.
3. Kerjakan tugas, verifikasi dengan lint + build.
4. **WAJIB: Setiap ada perubahan kode/file, perbarui `PROGRESS.md` DAN `AGENTS.md`** (tanggal, status tugas, keputusan/konvensi baru, langkah berikutnya). Jangan anggap tugas selesai sebelum kedua file ini diperbarui.
5. **KONSISTENSI SISTEM:** Jangan mengubah sistem yang sudah disepakati/dikonfigurasi tanpa konfirmasi eksplisit dari pengguna. Jangan melakukan commit/push otomatis tanpa perintah eksplisit.
6. Jangan commit/push kecuali diminta eksplisit oleh pengguna.

## Alur commit, push, dan deploy

1. Setelah pekerjaan selesai dan diverifikasi di lokal, pengguna akan memerintahkan commit & push.
2. Setelah diperintahkan, lakukan `git add`, `git commit`, lalu `git push` ke `main` (tanpa mengubah config git, tanpa force-push).
3. Push ke GitHub bersifat otomatis begitu diperintahkan.
4. **Deploy GitHub Pages tidak otomatis saat push.** Pengguna menjalankan **Actions → Deploy to GitHub Pages → Run workflow** di GitHub web.
5. Setelah deploy `success`, situs live menyajikan bundle terbaru — cirinya nama file `assets/index-*.js` berubah (bila tidak berubah padahal ada perubahan kode/secret, berarti ada yang belum ikut terbawa).
6. Jangan commit/push tanpa perintah eksplisit dari pengguna.
